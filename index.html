Routine changes today

  • Easy-Apply autopilot. Built an in-page driver (__probe / __fill / __adv / __run) that walks the modal, fills known fields, and submits — one CDP round trip per job instead of one per page. Persist it in localStorage.__autosrc and re-hydrate with eval(localStorage.getItem('__autosrc')) after each navigation; window.* helpers do not survive page loads. eval() worked on /search/* today, contrary to the 2026-08-08 note.
  • Radio questions have no usable label. Neither aria-label, <legend>, nor label[for] resolves on the current modal. Read the question by walking up ~6 ancestors and taking the first non-empty previousElementSibling text; read the Yes/No option by walking the radio's ancestors for a node whose text is exactly "Yes"/"No".
  • Resume page needs an explicit pick. The resume radio list is sometimes preselected and sometimes not, and a small second radio group ("I confirm all information is true") hides below the fold on the same page — select the largest group's first item, then answer any group of ≤3 with Yes.
  • Auto-answer whitelist, not blacklist. Only commute / remote / on-site / degree / notice / English / "confirm true" may be auto-answered Yes. Anything matching "experience with", "proficient in", "more than N years", or work-authorization halts the run for a human decision. Unknown-tech year fields default to 0, not 2.
  • Keep every in-page await under 45s — CDP Runtime.evaluate hard-times-out there. Cap the driver at 3–5 modal steps per call.
  • Content-search harvesting. Snapshot the shadow-root text at every scroll step and concatenate; posts unmount as they leave the viewport, so a single post-scroll snapshot loses most of them. Split the accumulated text on Feed post — the current DOM exposes no activity URNs, so post links can't be recovered and the "Re your post" line is dropped.
  • Phase 2 send path. SMTP (p2_send_2026-08-10.py) with per-recipient names beats the Gmail UI click loop: 24 sends in ~50s, no coordinate drift, no Drive-permission dialogs.
