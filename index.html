Routine changes today

  • Screenshot-before-type is mandatory. Recipe for any text field: screenshot → left_click → wait 1–2s → type → verify the value over JS. Skipping the screenshot or the wait produces a silent empty field.
  • Tab-chain the remaining fields. After the first field is filled, key Tab → type for each subsequent input. This sidesteps the bigger problem: clearing an "Invalid input" / "This field is required" message reflows the modal, so coordinates captured before the first fill are stale for every field after it.
  • Radios respond to JS .click(), text inputs do not. Set every radio and <select> (native value setter + change event) in one JS call, then re-read rects, then type. Note .checked read back in the same call is stale — verify visually or in a later call.
  • Radio index arithmetic bites. Groups are flat siblings in one querySelectorAll('input[type=radio]') list; count each group's option list from the modal text before indexing. An off-by-one silently answered "No" to right-to-work on the WorkMotion form.
  • Workable-mapped modals hide required fields below the fold. PartnerOne wanted a "Photo*" text field, WorkMotion a "LinkedIn Link*" — both invisible until the modal is scrolled, and both block Next with no visible error. Scroll the modal to the bottom before concluding the page is complete.
  • Scope the container by the "Apply to …" heading. div[role="dialog"] is still unreliable; walking up from the h2 until an ancestor has a button and >200 chars of text works on every ATS seen today (LinkedIn native, Workable, Ceipal).
  • Skip rule, applied consistently. If the screening questions are dominated by a stack outside React/Next/TS/JS — and honest answers would be 0/No across the board — skip rather than submit. Three postings were dropped this way.
