Routine changes today

  • Search-page scroller is <main>, not the window. window.scrollBy is a no-op on LinkedIn content search (body.scrollHeight stays ~1000px), so early harvests only saw the first screen. Scroll document.querySelector('main').scrollTop instead, in 4–5 steps max — more freezes the renderer and times out CDP at 45s.
  • eval() is blocked by CSP on /search/* (allowed on /jobs/*). Helper functions must be pasted inline on search pages; the localStorage-helper trick only works on job pages.
  • Job-description scoring via the guest API. /jobs-guest/jobs/api/jobPosting/<id> returns the full description as plain HTML and needs no scrolling — use it to keyword-score candidates before opening any modal. Fetching /jobs/view/<id>/ and regexing does NOT work: the description is client-rendered, and "react" matches LinkedIn's own bundle.
  • Applied-state pre-check. A job page containing "Application submitted" means a prior run already applied — check it before clicking Easy Apply. Caught 5 duplicates this run.
